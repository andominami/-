# 再生数カウンターのセットアップ

サイトの各資料が何回開かれたかを数えて、「再生数順」で並び替えられるようにする仕組みです。
Googleフォームの自動投稿(`google-form-to-github.gs`)とは完全に独立した、別のGoogle Apps Scriptプロジェクトとして動かします。

## 全体の流れ

```
サイト訪問者が資料を開く
   → assets/app.js が Apps Script の Web アプリへ通信(?action=hit&id=...)
   → Apps Script がプロパティに保存してある件数を+1

サイト表示時
   → assets/app.js が Web アプリへ通信(?action=counts)
   → 全資料の再生数を取得して、並び替え・表示に使う
```

## 1. 新しいApps Scriptプロジェクトを作る

1. [script.google.com](https://script.google.com) を開く
2. 「新しいプロジェクト」をクリック
3. プロジェクト名を「セミナー資料 再生数カウンター」等に変更(任意)
4. `コード.gs` の中身を全部削除し、このリポジトリの
   `automation/view-counter.gs` の中身を貼り付けて保存

## 2. Webアプリとして公開する

1. 右上の **「デプロイ」→「新しいデプロイ」**
2. 種類の選択(歯車アイコン)で **「ウェブアプリ」** を選ぶ
3. 設定:
   - 説明: 任意(例: 再生数カウンター)
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
4. 「デプロイ」をクリック
5. 権限の確認画面が出たら許可する(Googleアカウントの承認)
6. 発行された **ウェブアプリのURL**(`https://script.google.com/macros/s/.../exec` の形)をコピーする

このURLを教えてもらえれば、サイト側のコード(`assets/app.js` の `VIEW_COUNTER_API_URL`)に設定します。

## 3. 動作確認

デプロイ後、発行されたURLの末尾に `?action=counts` を付けてブラウザで開くと、
`{}`(まだ再生数が無いので空)が表示されれば正常に動いています。

```
https://script.google.com/macros/s/xxxxx/exec?action=counts
```

## コードを更新したとき

`view-counter.gs` の中身を書き換えた場合は、Apps Scriptエディタで保存した後、
**「デプロイ」→「デプロイを管理」→ 既存のデプロイの鉛筆アイコン→ バージョン「新しいバージョン」→ デプロイ**
という手順で更新してください(URLは変わりません)。「新しいデプロイ」を選ぶと
URLが変わってしまうので注意してください。
